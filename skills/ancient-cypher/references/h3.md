# H3 分镜、成本和踩过的坑

## 分镜规则

- **主歌、副歌：每条 4 句、10 秒**；快闪每人 2 句、6 秒（一人两句唱了四小节的给 10 秒）
- 提示词按**半句**写开唱和结束时间（精确到 0.01 秒，`make_shots.py` 从 whisper 词时间算），动作挂在半句上。第一期 32 条里 29 条一次过，口型匹配度 0.99+
- 镜头要近：**胸部以上或腰部以上**。全景里脸太小，口型检查会失败（匹配度 0.5）
- 话筒永远写「放在下巴高度，嘴露出来」
- 单人：`<id>_bust` + `<id>_face`（主唱）或 `<id>_sheet`（快闪）两张参考图
- 合唱：`venue` + 前排三人半身，前排写清左 / 中 / 右各是「参考图几号」的谁，加一句「每张脸只按自己的参考图，不许混脸」；后排人物用文字带过
- 防分身：写明「X 是台上唯一的女性，除了某某没人穿白衣」。不写的话，背景里会冒出两三个穿白衣、长得像女主唱的人
- 观众反应、DJ、片尾是无声 still，每条 5–6 秒，剪辑时可以切成几小段，分别盖不同的缝
- 片尾拉远镜头生成 6 秒，剪辑时放慢一半，正好垫在歌曲淡出下面

## 成本

国际价：768P 每秒 $0.08，2K 每秒 $0.13（国内 Key 按人民币扣，以后台为准）。

报价公式：所有素材秒数之和 × 单价，再留 30% 重抽余量。第一期 8 人、约 4 分钟：33 条 246 秒，一遍约 $19.7；加 3 段测试、4 条重抽，总共约 $25.5。

建议 768P 生成（1344×768），成片放大到 1080P；2K 贵约 60%，手机上看差别不大。

## 每批跑完的检查清单

1. `work/runs.jsonl` 里每条的 `qa.ok` 和 `corr`：0.99 左右算好，低于 0.9 要重抽
2. 每条抽 6 帧拼成一排，一屏看完：
   - 脸和定妆图一致吗？女主唱有没有变年轻？
   - 合唱里有没有分身、串脸？
   - 动作落在对的句子上吗？
   - 道具对吗（锄头别变成镐）？
3. 失败的列出来：原因、怎么改、价格，用户同意后再重抽

## 错误码

| 现象 | 原因 | 办法 |
| --- | --- | --- |
| `status failed, code 1027, output new_sensitive` | 输出被内容审核拦了，**不扣费** | 把动作描述改简单一点，再生成 |
| `HTTP 402 insufficient balance` | API 余额不够，不扣费 | 让用户去开放平台充值（网页版会员积分不能付 API） |
| `LIPS WON'T MATCH after 0.0s` | 脸太小、话筒挡嘴，或者 H3 重唱了一遍 | 改成近景、话筒放低，再重抽 |
| `invalid api key` | Key 和域名不配 | 国内 Key 用 api.minimaxi.com（或 api.minimax.cn），国际 Key 用 api.minimax.io |

## 其他坑

- faster-whisper 直接读 mp4 会被旧版 PyAV 卡住：先用 ffmpeg 转成 16k wav
- Windows 控制台是 GBK：所有脚本带 `PYTHONUTF8=1 PYTHONIOENCODING=utf-8` 运行
- 新版 ffmpeg 没有 `-filter_complex_script`，改用 `-/filter_complex 文件`（`package_film.py` 已经这么写）
- 毛笔字体 `MaShanZheng` 第一次会从 GitHub 下载，国内要走代理
